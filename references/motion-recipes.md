# 融合动作配方

吸收 Claude skill 的 UI 主体感、缓动、光感与结果接管，并按现有真实界面约束调整。以下是**制作起点**，不是声称已测出参考作者的工程参数。像素量基于 1920×1080；其他尺寸按比例调整。不要在同一小段塞满动作。

## 曲线与强度

- out-expo：`1 - 2^(-10p)`，p=1 时显式返回 1。启动快，尾部收稳，适合卡片和模块。
- out-back：`1 + (c+1)(p-1)^3 + c(p-1)^2`，c 可先用 0.65；回弹轻。附件落位可用，正文、指针和大型相机一般不用。
- quintic in-out：`p³(6p²−15p+10)`，两端速度与加速度平滑，适合单次起停的相机和交接；连续穿过的镜头不能每段都以零速度结束。它与 out-expo 不是同一个时间曲线。
- CSS 的 `cubic-bezier(.16,1,.3,1)` 是近似的出场缓动手感，不是指数函数的精确别名。跨 HTML/导出需要一致时共享数值函数。
- 模糊可由速度幅度映射，或用 `maxBlur * sin(πp)` 表示运动中段；入场允许初始模糊，等待移动的静止资产不应一直模糊。

## 19 种动作，按目的选择

| 动作 | 推荐起点 | 何时用 / 如何收尾 |
|---|---|---|
| 标题组装 | 0.35–0.6s；字/词错峰 0.04–0.08s | 章节标题。随机字符需确定性种子，只用于可替换的大标题，不乱改真实 UI 文字 |
| 清晰入场 | 0.3–0.45s；位移 20–60px；scale .96→1；blur 8–20→0 | 卡、菜单、短标题；正文阅读时必须落清晰 |
| 像素/马赛克揭示 | 0.4–0.6s | 可选品牌转场或示意成果。不能遮蔽实际操作或当作产品真的扫描 |
| 附件落入 | 0.25–0.45s；一次轻回弹 | 固定抓取点，图片比例不变，最后交给槽位同一矩形 |
| 短语打字 | 2–4 组短语；停顿 .12–.25s | 中文按词组；长文粘贴后突出重点。速度按字数和旁白调整，不统一套英语 chars/s |
| 指针移动 | 0.3–0.6s；in-out，轻弧线 | 目标与高亮同一相机；在按钮落下后才有反馈 |
| 局部 glow-click | 压下 .10–.18s；光感 .3–.6s | 普通提交。光从按钮中心发出，文字和点击区域不漂移 |
| 大范围光感交接 | .6–1s，仅关键节点 | 继承品牌强调色，旧画面在亮峰附近交给新画面；白闪可不用 |
| 快速聚焦 | .18–.3s 快速段，随后 .2–.4s 收稳 | 细节必须有分辨率支撑。不可为追求 3 倍推近让截图字糊成像素 |
| 开关/勾选 | .12–.2s，保留可读停留 | 按真实控件变化，不把 checkbox 擅改成 iOS 滑动开关 |
| 状态列表 | .15–.25s 错峰 | 仅真实状态；用户旁白需要的处理过程可以压缩，不能编造后台能力 |
| 扫描质感 | .4–.6s；低透明度 | 只用于有依据的分析过程或明确示意。人像识别/锁脸成功不能凭动效宣称 |
| 结果矩阵 | 占位错峰 .05–.1s；结果错峰 .1–.18s | 用真实不同结果，保持阅读顺序；不要把同图切碎假装多个生成 |
| 选中 → 放大接管 | 选中 .15–.25s；放大 .35–.6s | 选中缩略图沿同一路径变成大结果，边角和视频首帧一致 |
| 透视卡组 | 卡片偏转 2–6°；整组 .8–1.5s | 展示多候选与层级；逐渐减速到唯一主卡，停留时重要文本清楚 |
| 多卡归位 | 单卡 .3–.5s；错峰 .06–.14s | 标题/主图先到；不要同时从任意方向乱飞 |
| 动态大字 | .25–.45s 入场，之后阅读停留 | 章节/重点词，可短时拖影。不能把长提示词变成跳字特效 |
| 微推镜/视差 | 持续段 scale 1→1.01–1.04 或 1–3° | 可选。读字时允许静止，不能用漂移掩盖信息长时间不推进 |
| 流式回复/日志 | 一段出现 .6–1.5s，按实际文本调整 | 容器随预计算布局扩高；真实回复才可写入 UI，不编造系统完成语 |

## 可直接迁移的组合

**教程输入：** 全 UI 建立位置 → 聚焦输入区 → 附件落稳 → 原提示词分组揭示/粘贴 → 阅读落点 → 光标到真实按钮 → 轻压与局部光感 → 结果从结果区展开。

**主体绑定：** 正脸与三视图错峰进入各自位置 → 真实名称/标签 → 保存 → 主体库卡片。调用时保留同一头像与姓名，菜单选中项过渡到输入标签。若录屏没有拖放，飞入仅作资产归入示意。

**多结果：** 原画面缩小后退 → 首张结果先可辨认 → 后续错峰 → 旧输入退出 → 选中结果全屏。三视图内的人物是内容，不是可随意分开变形的三张卡。

**生成到成片：** 真实结果 UI → 将播放器画面裁切矩形平滑放大 → 该矩形的首帧匹配原视频 → 视频从对应时间连续播放。不要反复重置播放头或把原截图上的播放按钮留在成片里。

## 工具适配

- HTML/CSS：语义 DOM、transform/opacity、必要的 clip/filter；统一 `render(t)`，见 [运行方案](html-runtime.md)。
- Canvas：适合大量合成或固定帧渲染；文字、缩放与事件沿用同一时序，避免每帧图像解码。
- Remotion：用 `frame / fps` 求秒；共用数学缓动和 cue 表，显式媒体起点、视频时长与音量。只有需要回弹的对象才用 spring。随机值必须可复现。
- AE / 剪辑器：相机父级统一管理目标与标注，位置/缩放与模糊分层，按秒换算项目帧率；不要把 30fps 帧号直接搬到 60fps。
- 生成视频模型：适合实拍插入和氛围素材；需要准确字句、菜单和按钮的产品 UI 用真实素材/程序合成。
