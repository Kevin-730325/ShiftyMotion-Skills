# HTML / JavaScript：可回放、可导出的动效

本方法来自实际独立网页制作与浏览器通播检查。适用于网页预览和日后按帧导出，不要求使用 ChatCut。参考模块在 `assets/web-motion/`，复制进项目再按品牌与素材适配。

## 秒制时间与图层

时间表保存 `scenes: {id,start,end}`、输入事件、旁白区间和 SFX `{t,kind,gain,pan}`。所有时间单位为秒。渲染函数必须可以在 0→结尾、倒放 seek、随机时点和重复调用时得到同样画面；不要靠上一帧累积 `x += speed`。

建议层级：舞台背景 → 相机 → UI 原始坐标层 → 文本/附件/按钮 → 拖动临时层 → 光标/同坐标标注。播放控制放舞台外，不导进视频。把原图坐标通过同一矩阵变成目标坐标；不要分别猜光标与框的位置。

`assets/web-motion/motion-core.js` 提供曲线、矩形交接、短语事件和定位函数。返回值无副作用，可在 DOM、Canvas 和按帧渲染中共用。端点明确：隐藏对象不留残影，结束矩形与下一幕起点相同。

## 真实 UI 与提示词

优先级由目标决定：真实录屏剪辑/裁切，或真实截图拆层；只重画需要变化的元素。AI 生图不适合准确产品文字。

截图打字可采用：
1. 保存原截图、原像素尺寸、正文包围盒和行高。
2. 制作仅清空正文的底图，填色取自每行真正无文字的背景；避开滚动条、控件和渐变边界。不要从灰色滚动条采样填满输入框。
3. 按短语/行的可见区域揭示原图文字，光标跟实际行位置移动。除非逐字输入本身是教学重点，快速粘贴比漫长逐字更适合长提示词。
4. 完成状态直接恢复原截图，避免最后一行残缺。原图没展示的隐藏/滚动文字不能凭空补写。
5. 提示词 UI 保留原文，旁白可以概括；这是两个独立内容层。

复用同一 DOM 节点显示新资产时，**同时更新图片 src、裁切、宽高、遮罩和类型标记**，否则会出现新参数套旧图。动态容器预先算换行，不让字体晚加载改变行数。

## 播放与音效调度

- 有旁白时以 `audio.currentTime` 为主时钟；无长音轨可用 AudioContext 或暂停可恢复的单调时钟。RAF 只负责刷新，不另起一个独立计时体系。
- 音效 cue 先按时间排序。用 Web Audio 提前约 60–100ms 小窗口预排，不依赖 RAF 碰巧在点击那一帧调用 play。
- 暂停/跳转停止已排队的 source，重新定位 cue 索引；恢复从当前时间继续，不补播此前所有事件。切换版本重建时间表与声音源。
- 首次播放由用户手势启动/恢复 AudioContext。音效由项目自行选择，不预设素材路径或文件格式；对外显式展示加载失败。
- 旁白和 SFX 独立控制，必要时音乐另一路；语音期间轻降音效。阅读停顿、指针悬停通常不响。
- 自动化读 AudioParam.value 时注意浏览器空闲图优化：静音后的瞬时值不必等于已听输出；在实际触发音效的活动播放中测试开关。

## 原视频与首尾衔接

本机简单静态服务器不一定支持 HTTP Range。浏览器发 seeked 事件并不证明视频到了目标时间，应比较请求时间、`video.currentTime` 和实际画面。

可用 `scripts/serve_preview.py` 在项目目录启动支持字节范围的本地服务；脚本只监听 127.0.0.1。若环境不能精确 seek，则提取带正确时间戳的原帧，并预缓存需要的帧；VFR 素材不能简单把帧号当恒定源 fps。

浏览器中的实拍段可直接用原 video；进入时只设置一次正确时间，播放中只在偏差明显时校正，不能每一帧 seek。成片自己的声音与画面同源播放。制作片头缩略预览时，避免把预览已播放的几秒误当成结尾成片起点。

## 流畅度与预热

- 在移除加载遮罩前完成图片 decode、字体加载与视频 metadata；可按章节预载，避免一次加载不相关大素材。
- 缓存节点与图像，复用 transform/opacity；只在内容改变时改 text/src。DOM 创建、字体换行和音频解码不要落到动画关键帧里。
- 对首次出现的复杂 UI 可在加载遮罩下预热一次，再恢复封面。隐藏非活动幕，限制大面积 blur、阴影和不必要的透明层；`will-change` 不宜用于全站所有节点。
- 正文必须清晰落稳。静止等待的卡片不应因尚未进入运动区间而一直保留最大 blur。
- CSS blur 是柔焦近似，不是真正方向运动模糊；需要方向性可用少量离散时间采样叠加，并检查成本及拖影残留。

## 验证与后续导出

抽查每个章节的建立、输入、点击、结果落点和交接前后帧；至少一次原速通播。测试 seek、暂停、重播、音量、关闭旁白单听 SFX、全屏比例以及结尾连续实拍。记录 console/缺失资产、帧间隔分布和实测环境；60Hz 浏览器约 16.7ms 只是目标，不是所有设备保证。

离线导出共享 `render(t)` 与 cue 数据，按指定 fps 取样；音频按相同秒表离线混音，不把实时播放卡顿录进输出。返回真正渲染的成果，不把“写好了源码”当作视频已导出。用户只要网页时，在预览完成后结束该任务。

## v3：与 AE 共用视觉规则，分别处理渲染

视觉目标参照 [镜头与光效](camera-and-light.md)，不要逐项照搬 AE 数值。DOM 用统一相机容器／变换矩阵，适量 perspective 和 translateZ 表达层次；点阵数量较大、曲面扫光或多层合成适合 Canvas／WebGL。网页实现没有 AE 原生快门与景深的同等保证；CSS blur 是柔焦，真方向拖影需要按时间的多样本累积或适合的渲染器。

时间采样要覆盖对象与相机运动，用曝光区间中的多个 t 渲染同一场景，不仅复制当前位置成几层虚影。固定随机种子，seek 后点阵状态一致；避免每帧创建大量 DOM 节点。

矢量 logo 的分条揭示可用 SVG clipPath／mask；内部点阵与宽柔光共享圆角裁切，外扩光环独立于面板。高斯模糊与 SVG filter 留出边界，检查放大后裁切和亮度。字体先加载、确定最终排版，再用字素揭示；不把文字拆成 span 后丢掉字距与连字却称 1:1。

需要摄像机景深和大量柔光的 AE 交付，不因网页迭代方便就换成 HTML 成片。反之，用户要可交互网页，不交付只能播放的 AE 视频来代替；可将 AE 作为可选背景素材，但说明可编辑范围。
