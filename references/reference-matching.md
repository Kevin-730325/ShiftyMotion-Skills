# 参考片拆解与高保真复刻

适用于明确要求「尽量相同」「前几秒几乎一样」的任务。一般借鉴不必执行全部测量；已有参考和用户选择足够时直接推进，不反复确认品牌、时长或软件。

## 先拆设计，再写动画

1. 读取素材时长、分辨率、帧率／是否可变帧率、画面有效区域和声音。统一用秒记录参考时间与成片时间；若只做前 10 秒，抽样与交付都限定该范围。
2. 全范围粗抽样建立镜头顺序，再对转场、按钮、打字、字标组装加密。快速 0.1–0.3 秒事件要检查相邻源帧；每隔一秒截图无法判断甩镜。抽样结论明确标时间与覆盖范围，不称为逐帧遍历。
3. 每个状态记录：主体包围框、基线、留白、圆角、视角、图层顺序、光源位置、字体轮廓，以及开始／峰值／回收／离场时间。按有效画幅归一化坐标，避免把视频黑边与播放器 UI 算进构图。
4. 对镜头追踪同一个静态 UI 锚点及其宽度；用多个锚点判断是相机平移／缩放，还是组件独立移动。只有图片证据时说「实现推测」，不声称恢复了作者相机数据。
5. 建立可编辑的关键静态落点，先用相同时间画面比对字体、占屏比例、位置与材质，再补中间轨迹。误差通常先来自构图和时间，插件不能修复这些问题。

## 必须拆开的效果

- 开场：字标扫描组装、短水平光条、金属轮廓与亮条拼合、彩色面板显现、标题错峰上升。不能以一个图标淡入替代整串动作。
- 字体：APPS 等短大字的字宽、P 的内腔、S 的轮廓和字距非常显眼。找不到对应字体时，可从清晰正视帧重建短字轮廓；保留内孔，去除压缩锯齿，以矢量形状交付，明确来源。正文仍尽量使用真实字体和原生文本。
- 按钮：按下、回弹、箭头变星芒、由强调色升至近白、点阵波、扩散环、下一镜启动，各自有时间。遗漏任一关键状态会使「颜色差不多」仍看起来不像。
- 运镜：分别测启动时刻、方向、最大占屏比例、滚转角度、过冲与回收；还要观察落点之后有没有慢速移动。不能仅比较静帧，就称运镜一致。
- 品牌：符号几何来自目标品牌，条形揭示与底板来自参考的视觉机制。异形 logo 要按视觉重量居中，不能只对齐文件边界。

## 比较与迭代

按「构图／字形 → 时点与轨迹 → 光形与遮罩 → 材质 → 声音」修正最大差异。一次优先解决最影响观感的几项，避免同时改动所有参数后失去比较依据。

可使用 `scripts/contact_sheet.py`：

```bash
python scripts/contact_sheet.py --video reference.mp4 --compare remake.mp4 --times 1.8,4.7,4.85,5.0,5.85 --out comparison.jpg
```

工具依赖 Pillow 和 FFmpeg；FFmpeg 可用 PATH、`--ffmpeg` 指定，或由已安装的 imageio-ffmpeg 提供。不下载素材、不改原视频。两个文件必须使用已对齐的时间起点；需要重定时的镜头按事件单独对应，不能误以为同秒就是同状态。输出时间标签是请求采样时点，不是 VFR 源帧的 PTS 证明。

- 同时刻左右对照、半透明叠加或擦拭比单独看新版更容易识别漂移。品牌／内容有意不同的部分单独评估，不用全画面像素分数假装客观相似度。
- 原速连续看交接，慢放查最大速度附近与落点前后。静帧相似不保证运动相似；反过来，运动模糊帧不应按静态锐度评判。
- 做小范围预览再整片导出。最后改过柔光、遮罩或相机，就要更新最终视频、检查帧和包内重建代码，避免交付不同版本。
- 对外报告实际匹配部分和残余差异。用户要求 1:1 是制作目标；没有原工程、字体和相机曲线时不虚称逐像素相同。
