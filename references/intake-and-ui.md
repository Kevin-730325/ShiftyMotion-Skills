# 需求收集与可选 UI 流程

## 第一轮怎么问

先读用户现有要求和素材。只补缺失且会改变制作的项目：创作模式、产品/受众/用途、必须出现的内容、UI 真实性、背景来源与运动、声音、交付。用两三组短问题合并收集；用户可回答“其余你定”。不默认每个任务都做多轮采访，也不问用户选择具体 JS 库或填写相机参数。

1. **内容**：要解决什么沟通目标？必须展示哪些操作与结果，文案哪些不可改？复刻要哪段、保留哪些动作、替换哪些品牌？原创允许重组步骤吗？真实教程不编造按钮、数据和成功结果。
2. **画面**：如出现 UI，确认下面的 A/B/C。背景是否已有指定？选库中编号、原创还是外部？背景静止还是缓慢运动，喜欢漂移/波动光/网格扫光/视差哪种，强度低/中/高？
3. **交付与声音**：时长/画幅/分辨率/帧率，MP4、可编辑 AE、网页源码或透明背景；旁白、音乐、音效分别要不要，已有音频是否锁定时序？预算/截止时间/可用软件如影响方案再问。

已指定真 UI 或重绘，不重复询问。没有 UI 的品牌片直接跳过 UI 分支。重要决策写进简短制作摘要或事件表，保留用户已确认内容。

## A：严格真实 UI

先让用户提供已有材料，给出可选方案，不要求全交：

| 材料 | 可以做什么 | 要说明的限制 |
| --- | --- | --- |
| Figma 文件、组件、SVG、分层源文件与字体 | 保留结构，逐层动画；最适合可编辑交付 | 检查字体、组件状态、导出是否保留矢量 |
| 截图 | 真实像素底图、裁切、聚焦；按需要拆局部 | 截图仍是位图，不能承诺真矢量、隐藏状态或完整文字可编辑 |
| 录屏 | 真实操作顺序、反馈、结果与节奏依据 | 录屏是扁平画面，放大和重新运镜有清晰度限制 |
| 可访问网页/HTML 项目 | 经授权检查页面，获取当前可见布局、可用 SVG、字体和交互状态 | 登录/访问能力及字体等资源可能限制采集；先验证可行性，不保证一键转完整 Figma |

没有素材时，问用户选：提供截图/录屏；提供网页并授权采集；或接受 B/C。仍坚持真实 UI 且暂时没有来源时，先完成不依赖 UI 的部分，不用自绘界面冒充真实产品。

**Figma 是可选中间步骤**：已有文件或需要协作编辑时，若当前工具支持可读取/导出所需组件。AE 可按实际能力通过 SVG/PDF/AI、适用的导入工具或重建原生形状衔接；检查图层、文字与裁切，不能声称 Figma 文件必然直接变成原生 AE 工程。HTML 可直接使用原 SVG/文本，不强制绕 Figma。插件仅在明确需要、可用且获准时使用，无插件不阻塞其他已同意路径。

## B：允许按真实外观重绘

依据截图/录屏/网页重建需要运动的对象，保留关键文案与流程；确认允许哪些简化。交付说明“视觉重建”，区分原标志、近似字体、自绘组件与截图。需真矢量时用路径和原生文字重建，不能把截图封装进 SVG 假装矢量。

## C：允许概念 UI

按功能说明设计信息板、提示框、按钮和结果卡，不采集整站，不强制 Figma。问清必须真实的品牌/文案/功能，哪些允许设计。概念示意与实际功能演示区分，不能为了动画效果捏造产品能力。

## 素材检查与停止条件

只采集本片需要的界面和状态，脱敏账号等无关内容。发现访问失败、缺关键状态、字体不可用时说明缺口并给可选替代，不无限尝试抓取；将可选 UI 采集扩展为全站导出前需用户明确要求。记录原始矢量/文本/位图/重建来源。用户选择后直接推进，只有范围或真实性发生实质变化才重新核对。
