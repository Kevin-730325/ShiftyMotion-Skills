# UI 声音设计：本地素材优先

## 先选择，再编排

随包 `assets/sfx/` 有 83 个原始 WAV，8 类，总计约 2.2 MiB、26.08 秒。均为 44.1 kHz / mono / PCM 16-bit，直接导入 AE 或解码到 Web Audio；在最终项目混音时按输出要求重采样，不把重采样称作提升原始音质。无需在线下载才能使用。

1. 按视觉事件选类别，先在 `assets/sfx/index.html` 试听。查 `catalog.md` 或运行 `python3 scripts/sfx_catalog.py --category tap --max-duration 0.15 --limit 5`。只载入相关候选，不把 83 条全部塞入上下文。
2. 文件名前缀提供初始分类，不证明听感。尤其 `experimental` 不能直接称为粒子／玻璃；`transition` 不保证是宽空气 whoosh；`tap` 不自动等于键盘。先试听、结合画面确认再用，缺合适素材时留空或按需补充。
3. 同一产品选相近的一小套声音，重要程度用音量与层次区分。相近键击少量轮换，选择结果记录 seed / variant，不能每次 seek 随机换声音。
4. 来源文件原样保留；裁切、滤波、缩尾、变速等处理放在项目副本中，记录源 ID、处理参数和新锚点。不改 skill 内的原 WAV。

|类别|数量|优先尝试的事件|边界|
|---|---:|---|---|
|tap|15|按下、选中、轻接触|短且合适的样本才可作低电平键击|
|hover|8|焦点与细微反馈|普通悬停默认静音，避免鼠标经过一直响|
|transition|20|滑动、展开、镜头交接|10 组正／反向配对；reverse 是文件标记，不是已证明语义互逆|
|success|11|完成、结果收束|不为未知状态编造成功；不每项都播放完整提示|
|error|2|失败状态|不当作普通强调|
|warning|3|需要注意的状态|不与 success 随机混用|
|notification|14|提示、关键步骤、稀疏结果|密集事件降低强度或省略|
|experimental|10|扫描／光效等探索候选|先听再决定，不依据名字保证材质|

`tap-498z4`和 `tap-498z4-alt1` 的文件内容不同，均保留；不能仅凭“(1)”文件名删为重复。具体原名、哈希、时长、声道、配对和波形指标见 manifest。

## 与动画共用时间表

每条 cue 记录 `eventId, soundId, visualTime, anchorSeconds, startSeconds, gainDb, pan, playbackRate, bus, processing, reviewStatus`。

`startSeconds = visualTime - anchorSeconds / playbackRate`

manifest 只提供 onset / energy peak / last active **候选**，不替使用者决定锚点。按下用听到的触点，落位用接触，扫动用内部速度感峰，反向蓄能常用结束附近；确定之后写入 cue。时间伸缩或改包络后重新测。参考 VFR 使用源 PTS，项目事件按当前帧率；不要统一机械提前一帧。

- 输入按真实字符或短语增长形成短簇；停顿即停。粘贴长句不逐字符连发几十声。
- 按钮可以分为按下、回弹、亮点、点阵传播、光环展开，但不必每阶段都有声。普通按钮一个触点即可。
- 拖拽分拾起、移动、落位；主重音通常放接触，长鼠标路程不等于长声音。
- 相机扫声覆盖主要速度段；平缓漂移通常无声。按视觉方向适量声像，不能把单声道原件误称为立体声录音。
- 多卡同时出现按组点缀，避免十个重音叠在一帧。光环与音乐鼓点已有冲击时，减少额外低频。

## 混音与交付

默认输入比点击轻，点击比章节重音轻。不要将全部声音归一到同一峰值，也不要把短样本逐个拉到同一 LUFS。波形峰、RMS 与主观响度不同。多层叠加后检查总线，保留余量；sample-peak 检查不能冒充 true-peak 检查。

触点／运动／尾音分层，选必要的一到三层；旁白关键字附近让位，主频段避免挤在一起。近景与远景可用电平、高频与少量空间差异，别靠长混响掩盖不合适的样本。

先单声试听，再连画面，再连音乐与旁白；检查尖锐感、重复疲劳、切口、尾音截断、立体声与单声道、最终导出声画同步。没有可靠听音能力时注明仅做技术检查，不能称已完成主观验收。素材现成并不等于成片已经配声。

更细的组合与引擎落地见 [配声配方](sfx-cue-recipes.md)。素材来源与按需补充见 [在线补充](sfx-sources.md)。
